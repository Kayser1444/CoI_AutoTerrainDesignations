# Global mod settings storage

MaFi's modding guide documents `config.json` and `IMod.JsonConfig` for player-editable mod options. The current values travel in the world save. The guide documents a separate Controls API for registering mod keybinds. Review of the configuration, mod structure, implementation, keybind, and API reference pages found no documented directory or MaFi registration API for arbitrary settings shared across worlds. ## Vanilla preferences

The installed 0.8.8 game uses `UnityEngine.PlayerPrefs` for vanilla and mod keybind overrides. `ShortcutsStorage` stores the primary and secondary strings under action-derived keys and calls `PlayerPrefs.Save()`. The game also uses this store for preferences such as autosave interval and UI accessibility via `GlobalPlayerPrefs` and the public `PlayerPrefBool`, `PlayerPrefInt`, and `PlayerPrefEnum<T>` wrappers. The wrappers accept a caller-supplied key and persist to the same Unity store. [Local game reference, ShortcutsStorage](../../../../Mafi/Mafi.Unity/Mafi/Unity/InputControl/ShortcutsStorage.cs) · [GlobalPlayerPrefs](../../../../Mafi/Mafi.Unity/Mafi/Unity/GlobalPlayerPrefs.cs) · [PlayerPrefBool](../../../../Mafi/Mafi.Unity/Mafi/Unity/PlayerPrefBool.cs) · [PlayerPrefProperty](../../../../Mafi/Mafi.Unity/Mafi/Unity/PlayerPrefProperty.cs)

ATD could use Unity's documented API with an owned key such as `AutoTerrainDesignations.Settings`, including a JSON string through `SetString`/`GetString`. Unity also accepts integers and floats. The store is local to the application and user and lives in the current user's registry on Windows. It is independent of the ATD install folder, and its contents are less convenient to inspect or edit than a JSON file. [Unity PlayerPrefs](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityengine/playerprefs)

## Editable settings file

ATD can retain its JSON format under a mod-owned sibling of `Mods`, for example `%APPDATA%\Captain of Industry\ModConfigs\AutoTerrainDesignations\ATDsettings.json`. The vanilla `IFileSystemHelper.GameDataRootDirPath` exposes the configured game data root and avoids hard-coding the user path. The helper is available through dependency resolution during game initialization and through `IMain.FileSystemHelper`. `ModConfigs` is a mod convention used by Not Enough Keybinds. The installer swaps the directory for the mod ID under `Mods`, so the sibling path stays outside that operation. The Mori++ framework author documents using a separate settings folder for the same update issue. [Local game reference, IFileSystemHelper](../../../../Mafi/Mafi/Mafi/Core/IFileSystemHelper.cs) · [Game data root](../../../../Mafi/Mafi/Mafi/Core/FileSystemHelper.cs) · [GameBuilder](../../../../Mafi/Mafi.Core/Mafi/Core/Game/GameBuilder.cs) · [IMain](../../../../Mafi/Mafi.Unity/Mafi/Unity/IMain.cs) · [Installer](../../../../Mafi/Mafi.Unity/Mafi/Unity/UiStatic/Hub/Mods/ModInstaller.cs) · [Not Enough Keybinds](https://coigame.com/Mod/1183/Not-Enough-Keybinds) · [Keybind Framework v2.0.0 changelog](https://coigame.com/Mod/1104)

An editable external JSON file fits ATD's existing settings and manual tuning workflow. Migration can preserve an install-local settings file if it is still available when the new code runs. A replacement update can remove the source before the new mod starts, so those players would need a backup to recover their old global defaults.
